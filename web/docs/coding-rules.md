# Coding Rules

## General Principles

- Keep code simple, readable, and maintainable.
- Favor explicit logic over clever shortcuts.
- Add comments only when they clarify intent or non-obvious behavior.

## Naming

- Use descriptive names for classes, methods, and variables.
- Prefer domain language over technical jargon when possible.

## Testing

- Write tests for bug fixes and new behavior.
- Prefer deterministic, minimal tests.
- Validate the behavior that users rely on.

## Review Expectations

- Keep code style consistent with the repository.
- Avoid unrelated refactors in the same pull request.
